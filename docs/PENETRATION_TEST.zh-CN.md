# Guard 渗透测试计划与证据模板

更新日期：2026-11-13

## 1. 当前状态

**未执行。** 本文档是测试范围、方法和证据模板，不是测试结果。JVM 单元测试、Android 单元测试、Debug APK 构建和 PWA 构建不能替代独立渗透测试。

## 2. 测试目标

- 验证家长、设备、题库、通话和删除接口的认证与授权边界。
- 验证服务端输入校验、限流、SSRF 防护、错误处理和敏感信息泄露。
- 验证 PWA 的会话、危险操作确认、XSS/CSRF 暴露面和依赖风险。
- 验证 Android 导出组件、WebView、深链、媒体授权和本地数据边界。
- 验证部署层 TLS、Caddy/nginx 配置、LiveKit token 和 secrets 隔离。

## 3. 范围

| 层 | 重点 |
| --- | --- |
| Ktor API | 认证、所有权、IDOR、SQL/JSON 注入、限流绕过、错误信息、上传大小、事务删除 |
| 家长 PWA | 会话存储、XSS、CSRF、开放重定向、删除流程、第三方脚本和构建产物 |
| Android DPC | exported 组件、intent 重定向、WebView、媒体/截图授权、备份标志、日志、Keystore |
| 设备配对 | 配对码暴力、重放、设备公钥替换、token 刷新、吊销竞态 |
| 题库/上游 | 签名验证、密钥轮换、Delta 回退、SSRF、DNS rebinding、重定向和大小限制 |
| LiveKit | 房间命名、token 权限、孩子同意前签发、房间复用和过期 |
| 基础设施 | TLS/HSTS、反向代理头、真实客户端 IP、数据库/备份暴露、secrets 和日志 |

不在范围：Android 内核漏洞、专业芯片侧信道、云厂商控制面、已 root 设备的无条件绕过。发现这些方向的边界问题仍应记录。

## 4. 方法与基线

- OWASP ASVS（Web/API）和 MASVS（Android）作为检查框架。
- 手工测试优先，自动扫描作为补充；所有 High/Critical 发现必须有可复现步骤和证据。
- 测试环境使用独立域名、数据库和测试账户，不得复用真实家庭数据或正式签名密钥。
- 所有破坏性测试（账户删除、密钥轮换、设备擦除）只在专用测试环境执行。
- 未授权、认证后越权、跨账户访问和删除传播必须分别验证。

## 5. 必测用例

| ID | 用例 | 期望 |
| --- | --- | --- |
| AUTH-01 | 未带 token 访问家长和设备接口 | 401，无业务数据 |
| AUTH-02 | 过期、篡改、错误 audience 的 JWT | 401 |
| AUTH-03 | 家长 A 访问家长 B 的设备、用量、审计、题库和截图 | 404 或统一拒绝，不泄露存在性 |
| AUTH-04 | 设备 token 吊销、设备删除或家长删除后重试 | 401/403，旧 token 不能恢复权限 |
| AUTH-05 | 注册/登录暴力尝试 | 限流生效，响应不泄露账户存在性 |
| IDOR-01 | 遍历设备、截图、通知、求助和调用 ID | 无权访问时统一拒绝 |
| DEL-01 | 错误密码、邮箱、确认词删除账户 | 403，账户和数据保留 |
| DEL-02 | 正确删除后检查全部表和 token | 目标家庭清零，另一家庭不受影响 |
| SSRF-01 | 上游地址指向 loopback、私网、链路本地、带凭据/fragment、重定向 | 拒绝且不发起内网请求 |
| QUIZ-01 | 坏签名、错误 key id、版本回退、Delta 基线不匹配 | 拒绝或回退完整包，active 包不破坏 |
| MEDIA-01 | 孩子未接受时申请 LiveKit token 或截图 | 拒绝，不产生采集 |
| AND-01 | exported Activity/Receiver/Service 和深链边界 | 不能绕过管理或读取敏感数据 |
| WEB-01 | 存储型/反射型 XSS、危险 HTML 注入、第三方资源 | 不执行不可信脚本 |
| INFRA-01 | 反向代理头伪造、直接访问后端、目录/备份暴露 | 不能绕过 TLS/限流或读取 secrets |

## 6. 严重度

| 等级 | 定义 | 发布处理 |
| --- | --- | --- |
| Critical | 跨租户全量数据、远程接管、正式密钥泄露、静默监控 | 禁止发布 |
| High | 单家庭敏感数据越权、认证绕过、持久化代码执行 | 修复或正式风险接受 |
| Medium | 有限信息泄露、限流/CSRF/配置弱点 | 发布前修复或记录 |
| Low | 加固建议、低影响信息暴露 | 可进入后续迭代 |
| Info | 观察项和最佳实践 | 记录 |

## 8. 入口与退出条件

入口：测试环境可用、账户/设备数据隔离、构建可追溯、正式 secrets 不在测试环境、紧急联系人和删除流程已准备。

退出：所有 Critical/High 已修复并复测；Medium 有修复或书面接受；测试报告、SBOM、日志和发布哈希归档；结论由安全负责人签字。
