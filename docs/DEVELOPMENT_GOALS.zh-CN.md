# Guard 开发目标

## 1. 产品定位

Guard 是一个 Android 优先的“家长端 + 孩子端 + 设备策略服务”系统，目标是在家庭约定和孩子知情的前提下，帮助减少游戏、短视频和社交应用的失控使用，同时保留学习、通信、紧急求助和家长协助能力。

产品名称暂定为 **Guard 家长监护模式**。第一版面向一台由家长实际管理的专用 Android 手机或平板，不把个人手机上的隐式接管作为产品承诺。

## 2. 需求转化

| 原始想法 | 可交付的产品目标 | 实现边界 |
| --- | --- | --- |
| 获得手机“超级管理权限” | 使用 Android Enterprise `Device Owner` 管理专用设备；备选为受管工作资料 | 普通 App 不能成为系统 root；正式部署需要受支持的注册流程 |
| 控制游戏时间 | 按应用、类别、日期、时段和每日额度制定策略；用量接近上限时提醒，超限后阻断或进入任务页 | 使用公开的 `UsageStatsManager`、`DevicePolicyManager` 等能力 |
| 控制可用软件、可访问软件 | 应用白名单/黑名单、临时放行、学习时段白名单、系统设置限制 | 设备管理员可控制的范围取决于 Android 版本、厂商和 provisioning 状态 |
| 随时视频、通话 | 家长与孩子之间的一键联系、视频通话和设备协助 | 只能在双方授权、前台可见和权限明确时工作，不监听第三方电话或隐蔽开摄像头/麦克风 |
| 截屏 | 在孩子端主动同意后进行屏幕共享或单次截图，并显示系统/应用状态提示 | 不承诺绕过 `MediaProjection` 授权静默抓屏；每次访问可审计、可撤销 |
| 弹出考题后继续使用 | 配置触发条件、题库、题型、难度、重试次数、冷却时间和奖励时长；答对可获得有限时长 | 不以刁难或无限循环为目标；支持跳过、求助和家长紧急解锁 |
| 题库连接上游更新 | 题库采用版本化、签名、可回滚的更新包；支持自建服务或可信上游 | 更新包必须校验来源、签名、版本和内容安全；离线时使用本地题库 |
| 免退出、不可杀后台 | 开机恢复策略、前台服务、策略持久化、状态校验和异常恢复 | Android 不允许普通应用绝对不可杀；不能阻止恢复出厂或系统管理员操作 |
| 不可卸载 | 在 `Device Owner` 模式下限制非管理员卸载和退出管理 | 管理员必须有可审计的解锁/解除管理流程；不能隐藏自己或阻止设备所有者恢复出厂 |

## 3. 安全与伦理底线

以下内容明确不属于本项目目标：

1. 隐藏应用图标、伪装进程、隐蔽安装或未经孩子/设备所有者同意的监控。
2. 读取私人聊天、短信正文、键盘输入、密码、第三方通话内容或通讯录以外的无关数据。
3. 在无可见提示和明确授权时打开摄像头、麦克风、屏幕录制或持续上传定位。
4. 利用 root、漏洞、无障碍服务滥用或厂商缺陷绕过 Android 权限与用户选择。
5. 设计成无法恢复的“锁死”设备。必须保留家长恢复码、紧急通信和解除管理/恢复出厂说明。

产品必须提供：家长身份认证、孩子端状态提示、权限与数据访问日志、最小权限、传输加密、密钥轮换、离线安全策略、数据删除和应急解锁。

## 4. 第一阶段目标（MVP）

### 4.1 设备注册与管理员

- 支持 Android 8.0+ 的专用测试设备，优先验证 Android 12–15。
- 通过标准 provisioning 将孩子端注册为 `Device Owner`；注册前明确提示可能需要恢复出厂。
- 使用家长 PIN/口令保护策略变更；敏感操作要求再次验证。
- 记录设备状态：是否为 Device Owner、策略版本、最后同步时间、策略校验结果。
- 开机后恢复策略，策略未验证成功时不能向用户显示“保护已开启”。

### 4.2 应用与时间策略

- 展示已安装应用和应用类别，支持白名单、阻断名单和始终允许名单。
- 支持工作日/周末、学习/睡眠/自由时段和每日额度。
- 支持按应用累计时长、连续使用提醒、临时奖励时长和家长一次性放行。
- 额度耗尽后进入全屏、可退出的任务页；任务页显示原因、剩余等待时间、求助和紧急联系人。
- 所有本地策略具有版本号、更新时间和回滚版本，离线状态仍按最后一个已验证策略执行。

### 4.3 题目闸门

- 家长可配置触发方式：达到总时长、进入指定应用、连续使用、某个时间段开始或手动触发。
- 支持单选、多选、判断、简答和图文题；题目可按科目、年级、难度、语言和标签筛选。
- 支持答对奖励时长、答错冷却、重试次数、题目频率、每日上限和随机抽题。
- 支持本地题库导入、题库版本、签名校验、差分更新、失败回滚和离线缓存。
- 题目策略不能绕过紧急电话、家长联系、无障碍需求或法律要求的安全功能。

### 4.4 同步与隐私

- MVP 优先采用本地优先：设备无网时仍能执行策略，联网后增量同步。
- 同步内容最小化：策略、用量摘要、题目答题结果和设备健康状态；默认不上传屏幕内容、麦克风或摄像头数据。
- 服务端接口支持设备密钥、短期令牌、重放保护、请求签名和策略签名。
- 家长端能查看策略变更、设备在线状态、应用用量摘要和题目结果，并能撤销会话。

## 5. 第二阶段目标：透明远程协助

该阶段必须在 MVP 的本地策略和审计能力稳定后实施：

- 家长发起孩子端可见的一对一语音/视频通话；孩子端显示摄像头、麦克风状态和结束按钮。
- 在孩子端确认后开始屏幕共享或单次截图；共享过程中保持明显状态指示，停止后立即撤销会话令牌。
- 支持家长发送“请回拨”“请完成任务”等通知，不支持后台录音、录屏或采集第三方通信内容。
- 默认不保存媒体；如确有保存需求，必须单独征得同意、加密存储并设置自动过期。

## 6. 第三阶段目标：设备韧性与运营

- 使用 `BOOT_COMPLETED`、前台服务、WorkManager/AlarmManager 和策略完整性校验恢复运行状态。
- 在 `Device Owner` 模式下使用锁定任务、应用挂起、用户限制和安全设置等公开策略能力。
- 对策略服务异常、时间漂移、篡改配置、回滚和断网分别设计恢复路径。
- 支持签名 APK/策略/题库更新，保留上一版本并提供失败回滚。
- 提供诊断导出、家长恢复码、解除 Device Owner 的官方流程和专用设备恢复说明。

“不可杀死后台”与“不可卸载”只作为受管设备上的**增强韧性指标**，不是绝对安全承诺。系统更新、恢复出厂、OEM 工具、物理持有者和更高权限管理员始终是边界条件。

## 7. 推荐技术架构

### 7.1 设备端

- Kotlin + Android SDK；核心策略组件实现为 Device Policy Controller（DPC）。
- `DevicePolicyManager`：设备所有者、应用挂起、用户限制、锁定任务和受管配置。
- `UsageStatsManager`：应用使用统计；避免用无障碍服务作为主要拦截机制。
- Jetpack Room/DataStore：策略、题库、答题和审计记录；敏感字段使用 Android Keystore 保护密钥。
- WorkManager/前台服务：同步、健康检查和开机恢复，遵守 Android 后台限制。
- MediaProjection/WebRTC：仅用于授权后的屏幕共享或通话，并保留可见状态。

### 7.2 家长端与服务端

- 家长端可先做 Android/Web 管理台，后续再决定是否使用 Flutter 共享 UI。
- 服务端使用版本化 REST/WebSocket API；策略和题库包都采用签名校验。
- 首选自托管或可替换后端，避免将家庭敏感数据绑定到单一供应商。
- 默认只保存必要的用量摘要和审计事件；媒体默认不落盘。

## 8. 开源复用策略

复用分为“可直接作为依赖/基线”“提取设计并重写”“仅作参考”三类。引入前必须确认许可证、维护状态、依赖许可证、隐私行为和安全审计结果。

| 项目 | 许可证/状态 | 计划复用方式 | 结论 |
| --- | --- | --- | --- |
| [ShalomMaman/android-lockdown-dpc](https://github.com/ShalomMaman/android-lockdown-dpc) | Apache-2.0；Device Owner DPC、白名单、锁定任务、自更新；当前为 pilot | 优先作为设备策略基线，先做代码审计和专用设备验证 | 最优先候选，但不能直接视作生产级安全产品 |
| [googlesamples/android-testdpc](https://github.com/googlesamples/android-testdpc) | Apache-2.0；Google 的 DPC/API 参考实现 | 复用 provisioning、DevicePolicyManager 调用方式和测试方法 | 参考实现，不直接作为完整产品 |
| [flxapps/DetoxDroid](https://github.com/flxapps/DetoxDroid) | GPL-3.0；活跃的数字戒断/使用控制项目 | 参考用量展示、专注模式和交互；若复制代码，必须接受 GPL 传播义务 | 优先参考，谨慎代码复用 |
| [childscreentime/cst](https://github.com/childscreentime/cst) | README 声称 MIT，但仓库元数据的许可证状态需复核 | 参考全屏阻断、额度和题目/奖励交互 | 完成许可证确认和安全审计前不复制代码 |
| [JordyHers-org/Times-up-flutter](https://github.com/JordyHers-org/Times-up-flutter) | Apache-2.0；家长控制和同步示例，更新较慢 | 参考家长端/孩子端数据模型与同步流程 | 可参考，需重做 Android 策略层 |
| [xMansour/KidSafe](https://github.com/xMansour/KidSafe) | MIT；项目维护度有限 | 参考产品信息架构和家长控制流程 | 仅参考，不能作为安全基线 |
| [Daycompass/Daycompass](https://github.com/Daycompass/Daycompass) | AGPL-3.0；自托管 screen-time 后端 | 评估其数据模型和自托管部署；必要时通过 API 集成 | 代码集成前单独评估 AGPL 影响 |
| [muhammad-fiaz/QuizApp-Flutter](https://github.com/muhammad-fiaz/QuizApp-Flutter) | MIT；题目 UI 模板 | 可提取题目展示交互和组件设计 | 只复用 UI 思路/组件，题库安全逻辑自行实现 |

### 复用决策

推荐顺序是：

1. 以 `android-lockdown-dpc` 为候选 DPC 基线，结合 `android-testdpc` 补齐 Android Enterprise 测试。
2. 从 `DetoxDroid` 和 `childscreentime/cst` 提取使用时长、阻断和恢复交互，但先完成许可证及隐私行为审查。
3. 题库 UI 可借鉴 MIT 模板；题库签名、策略执行和同步协议不直接照搬示例项目。
4. 通话/屏幕共享在第二阶段再评估 Jitsi/LiveKit 等开源 WebRTC 方案，先验证权限、提示和数据留存设计。

## 9. 里程碑与验收标准

### M0：可行性和合规审计

- 在两台不同 Android 版本的专用测试设备上完成 Device Owner 注册和解除管理。
- 建立第三方代码清单、许可证清单、依赖扫描和隐私数据流图。
- 明确厂商差异、恢复出厂风险、家长恢复码和应急联系策略。

### M1：本地策略 MVP

- 重启后策略恢复；应用白名单、时段和额度在离线状态可执行。
- 管理员 PIN 无法从孩子端普通 UI 直接绕过；策略变更有审计记录。
- 设备失去 Device Owner 或策略校验失败时明确报警，不显示虚假的“保护中”。

### M2：题库闸门与同步

- 题目频率、题库筛选、答对奖励、答错重试和每日上限均可配置。
- 恶意/损坏/降级题库无法覆盖本地有效题库；更新失败自动回滚。
- 断网、重启、时钟变化、低电量和进程重启测试通过。

### M3：透明远程协助

- 语音/视频、屏幕共享和截图都能看到授权状态、开始/结束状态和审计记录。
- 未授权时无法启动采集；结束会话后令牌失效；默认没有媒体持久化。

### M4：发布候选版

- 完成威胁建模、依赖和许可证审核、渗透测试、恢复出厂演练和数据删除演练。
- 发布文档明确支持的 Android 版本、厂商限制、Device Owner 注册方式和恢复流程。

## 10. 首个实施任务清单

1. 拉取并锁定候选 DPC 基线，记录 commit、许可证和依赖，不直接跟随浮动分支。
2. 建立 Android 专用设备测试矩阵：Android 12/13/14/15，至少两家厂商。
3. 编写最小 Device Owner 注册、策略读取、应用白名单和开机恢复验证。
4. 定义策略 JSON、题库包格式、签名字段、版本规则和回滚状态机。
5. 加入家长 PIN、审计日志、应急解锁和解除管理流程，再实现全屏阻断。
6. 通过本地离线测试后，才接入家长端同步；远程视频/截图不进入 MVP。

## 11. 成功定义

Guard 的成功不是“控制得越强越好”，而是：家长能在透明、可撤销、可审计的前提下限制分心应用；孩子在紧急联系、学习和健康需求上不被锁死；设备重启、断网和普通误操作不会轻易失去策略；系统在 Android 的公开安全边界内工作，并且开源复用有明确许可证和维护责任。
