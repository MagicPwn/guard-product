# Guard 设备恢复与重新 Provisioning 演练

更新日期：2026-11-13

## 1. 状态

- 代码路径、JVM 单测和 Android 模拟器验证：部分已覆盖。
- 真实 Device Owner 设备上的紧急访问到期、解除管理、恢复出厂和重新 provisioning：**未执行**。

恢复演练必须使用可丢弃的专用设备。恢复出厂会清除设备数据，不能在生产家庭设备上试错。

## 2. 前置条件

- 一台可恢复出厂的 Android 测试设备，记录型号、Android 版本、API level 和固件构建号。
- ADB、设备 Owner 测试账户、家长 PWA 测试账户和测试服务端。
- 已知的 Guard `versionName`/`versionCode`、APK 哈希和策略公钥。
- 设备电量充足，测试数据可丢弃，正式 secrets 不在测试环境。
- 执行人和见证人；逐步截图、日志和命令输出归档。

## 3. 场景 A：紧急访问窗口

1. 启动紧急访问，记录开始时间、结束时间、通知内容和审计事件。
2. 验证窗口内只有 Guard 管理的应用限制临时释放，系统策略、维护模式和 kiosk 不会被关闭。
3. 分别测试提前结束、到期、重启和时钟异常；每次都应恢复 Guard suspension 和受管策略。
4. 验证窗口内不会产生普通使用提醒，结束后提醒会话按设计重置。
5. 验证普通孩子端无法通过 UI 延长窗口或重复打开。

预期：每个结束条件都恢复限制；审计包含原因和结果；设备未出现半完成状态。

## 4. 场景 B：解除 Device Owner

1. 在 kiosk 或维护窗口活跃时尝试解除，确认被拒绝且管理权保留。
2. 关闭活跃窗口，进入恢复台，完成二次 PIN。
3. 观察逐级释放：Guard suspension、受管策略、隐藏包、kiosk/导航护栏。
4. 在真正调用 `clearDeviceOwner` 前回读 suspension 和策略状态，确认已释放。
5. 解除后验证设置、启动器、网络和应用恢复可用；检查是否仍有残留隐藏包或锁定任务。
6. 重新启动，确认不会重新进入受管 kiosk，也不会留下无法恢复的管理状态。

预期：解除过程可观察、可回读、可恢复；失败时不会提前失去 Device Owner 权限。

## 5. 场景 C：恢复出厂与重新配对

1. 记录当前设备 ID、家长账户和配对状态。
2. 在家长端吊销设备，验证旧设备 token 立即失效。
3. 执行恢复出厂；确认设备数据清除后无法通过旧凭据访问服务端。
4. 用 ADB 或 Android Enterprise QR 重新 provisioning，确认 Device Owner、策略公钥和服务端地址正确。
5. 重新生成配对码并在家长端认领；验证新设备记录、策略下发、用量上报和审计。
6. 验证旧设备记录不会错误复用新设备的 token，另一个家庭也不受影响。

预期：恢复后的设备是新的管理身份；旧 token 不能复活；重新 provisioning 文档与真实步骤一致。

## 6. 场景 D：丢失或被盗设备

1. 家长端吊销设备；验证设备 token、通话/截图和管理接口立即拒绝。
2. 明确服务端吊销不等于远程抹除：设备本地缓存策略和本地数据可能仍在。
3. 如组织有受管擦除能力，执行擦除并记录结果；如没有，明确告知用户联系运营商/执行恢复出厂。
4. 复核设备是否还能从缓存策略继续限制应用，以及离线状态下的真实行为。
5. 将设备标记为丢失/退役，禁止重新使用旧设备 ID。
